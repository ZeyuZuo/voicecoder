# 编码前准备清单

日期：2026-05-28

## 开发顺序建议

你的判断是对的：先做外壳和语音，再结合 Codex。

建议分四段开发：

1. **桌面外壳**：Tauri + React + TypeScript，先实现项目选择、文件树、布局、状态存储。
2. **语音链路**：先接腾讯云实时说话人分离，得到稳定的 `{speaker, text, timestamp}` 流。
3. **需求整理**：把语音/文本转成结构化需求状态，支持总结、追问、确认。
4. **Codex 集成**：先用 `codex exec --json` 跑通自动改代码，再升级到 `codex app-server` 做完整事件流和审批。

这样做的原因是：Codex 集成复杂度高，但它依赖前面的项目管理、对话、状态、文件和预览能力。先把应用外壳和输入链路做好，后面接 Codex 才不会被 UI 和基础设施卡住。

## 跨平台约束

第一版可以先在 Fedora 上开发和验证，但代码结构必须按跨平台桌面应用设计，不能写成只适配 Linux 的实现。

需要提前遵守这些约束：

- 前端 UI 使用 React/TypeScript，避免依赖特定系统的浏览器能力。
- 本地能力集中放在 Tauri Rust 后端，不在前端散落调用系统命令。
- 文件路径统一用 Rust `PathBuf` / Tauri path API 处理，不手写 `/` 或 Windows 盘符逻辑。
- 子进程管理抽象成 provider，例如 dev server、Codex、ASR helper 都通过统一接口启动/停止/读日志。
- 平台差异集中放在 `platform` 层，例如 shell、终端、麦克风权限、文件选择器、系统托盘、自动更新。
- 凭证存储后续接系统 keychain，不长期依赖明文 `.env`。Fedora 开发期可以用 `.env`，正式版要换成跨平台安全存储。
- CI/打包后续至少覆盖 Linux、Windows、macOS。Tauri 官方支持按平台生成安装包，Linux 可发 RPM/AppImage，macOS 需要签名和 notarization，Windows 需要 WebView2 和安装包签名。

这不影响当前在 Fedora 上先开发，但会影响目录结构和接口设计。

## Fedora 还需要安装的系统依赖

Tauri 2 在 Linux 上需要 WebKitGTK、GTK、appindicator、librsvg、libxdo 等开发包。当前本机检查到以下 pkg-config 包缺失：

- `webkit2gtk-4.1`
- `gtk+-3.0`
- `appindicator3-0.1`
- `librsvg-2.0`
- `xdo`

建议先安装：

```bash
sudo dnf install \
  webkit2gtk4.1-devel \
  openssl-devel \
  curl \
  wget \
  file \
  libappindicator-gtk3-devel \
  librsvg2-devel \
  xdotool-devel \
  gtk3-devel
```

如果 Fedora 包名变动，优先用下面命令定位：

```bash
dnf provides 'pkgconfig(webkit2gtk-4.1)'
dnf provides 'pkgconfig(appindicator3-0.1)'
dnf provides 'pkgconfig(xdo)'
dnf provides 'pkgconfig(librsvg-2.0)'
dnf provides 'pkgconfig(gtk+-3.0)'
```

安装后可用这些命令确认：

```bash
pkg-config --modversion webkit2gtk-4.1
pkg-config --modversion gtk+-3.0
pkg-config --modversion appindicator3-0.1
pkg-config --modversion librsvg-2.0
pkg-config --modversion xdo
```

## 腾讯云 ASR 准备

第一版建议使用腾讯云“实时说话人分离（WebSocket）”。

你需要准备：

- 腾讯云账号；
- 开通语音识别 ASR 服务；
- 确认已开通“实时说话人分离”能力；
- `SecretId`
- `SecretKey`
- `AppID`
- 服务地域/接口配置；
- 计费方式和余额；
- 麦克风采集授权；
- 一段 16kHz/16bit/mono PCM 测试音频，便于排查客户端问题。

建议把凭证放在本地 `.env`，不要写进代码仓库：

```bash
TENCENTCLOUD_SECRET_ID=...
TENCENTCLOUD_SECRET_KEY=...
TENCENTCLOUD_APP_ID=...
TENCENT_ASR_ENGINE_MODEL_TYPE=16k_zh
TENCENT_ASR_VOICE_FORMAT=1
```

实际变量名后续可以按实现调整。关键点是 SecretKey 只放在 Tauri Rust 后端或本地配置里，不暴露给前端页面代码。

### SDK 还是 API

建议第一版使用 **腾讯云 WebSocket API 直连**，不把主链路绑定到腾讯云 SDK。

理由：

- 实时说话人分离官方接口本身就是 WebSocket 协议，核心逻辑是生成签名 URL、发送实时音频分片、接收 JSON 结果。
- 我们的主后端是 Rust/Tauri，腾讯云 ASR SDK 覆盖的是服务端、客户端、前端和小程序等场景，但 Rust 不是它的主要桌面集成路径。
- 跨平台桌面端更需要自己控制音频采集、重采样、分片节奏、断线重连、错误处理和日志。
- 直连 API 只依赖标准能力：HMAC-SHA1、Base64、URL encode、WebSocket、JSON，Rust/Node/浏览器都容易实现和测试。
- 未来如果替换到讯飞、阿里云、FunASR，本地只需要换 ASR provider，不会被腾讯 SDK 的接口形状锁死。

腾讯 SDK 可以作为参考和快速验证工具，但不建议作为正式核心依赖。

推荐封装形态：

```text
AsrProvider
  ├─ connect(config)
  ├─ sendAudioChunk(bytes)
  ├─ onPartialResult(event)
  ├─ onFinalSentence(event)
  ├─ onSpeakerSentence(event)
  └─ close()

TencentRealtimeSpeakerProvider
  ├─ buildSignedWebSocketUrl()
  ├─ normalizeAudioToPcm16kMono()
  ├─ send200msFrames()
  └─ parseSpeakerSentences()
```

腾讯云实时说话人分离接口关键参数：

- `engine_model_type=16k_zh_en_speaker`
- `voice_format=1`，第一版先使用 PCM
- `voice_id` 每次连接都重新生成 UUID
- `needvad=1`
- 16kHz/16bit/mono PCM 时，建议每 200ms 发送 6400 字节
- 返回结果里关注 `sentences.sentence`、`sentences.sentence_type`、`sentences.speaker_id`、`sentences.start_time`、`sentences.end_time`
- `speaker_id` 初期可能是 `-1`，后续才会稳定到 `0-9`

## Codex 准备

当前本机已经安装 Codex CLI，后续还需要确认登录状态：

```bash
codex login
codex doctor
```

MVP 阶段推荐先使用：

```bash
codex exec --json --sandbox workspace-write --cd <project-dir> "<coding prompt>"
```

正式集成阶段再使用：

```bash
codex app-server
codex app-server generate-ts --out ./src/codex-protocol
```

Codex 相关注意事项：

- 不要依赖闭源 Codex Desktop App；
- 不要把 Codex CLI fork 作为第一步；
- 先把 `codex` 当外部二进制调用；
- app-server 协议仍是 experimental，要保留版本兼容层；
- 中国大陆网络/合规环境下，Codex 不应作为唯一 coding backend。

## 本地项目结构建议

正式编码前建议先确定目录：

```text
voicecoder/
  docs/
  app/
    src/
    src-tauri/
  experiments/
    asr-tencent/
    codex-exec/
```

建议先做两个小实验：

1. `experiments/asr-tencent`：只验证麦克风采集、音频切片、WebSocket 发送、实时返回文字和 speaker id。
2. `experiments/codex-exec`：只验证给一个测试前端项目发 prompt，读取 `codex exec --json` 事件流。

两个实验都通过后，再把能力移入正式 Tauri app。
