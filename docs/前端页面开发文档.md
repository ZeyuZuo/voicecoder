# 前端页面开发文档

本文档用于指导 VoiceCoder 前端页面开发。页面视觉和交互参考 `demo_images/demo1.png`、`demo_images/demo2.png`、`demo_images/demo3.png`，但产品能力以 `docs/需求文档.md` 和 `docs/roadmap.md` 为准。

## 1. 页面定位

VoiceCoder 不是普通聊天应用，也不是传统 IDE。它的第一屏应当是“对话驱动的本地编码工作台”：

- 左侧负责导航、项目和会话。
- 中间负责需求输入、澄清、确认和 Agent 过程。
- 右侧负责文件、浏览器、审查、终端等开发反馈。

用户的主线行为是：

```text
选择项目
  ↓
输入或说出需求
  ↓
AI 澄清并整理需求
  ↓
确认生成 Coding Prompt
  ↓
Agent 修改代码
  ↓
查看文件、diff、预览和日志
```

## 2. 整体布局

桌面端采用三段式布局。

### 2.1 左侧导航栏

用途：承载全局入口、项目列表、会话列表、设置入口。

建议尺寸：

- 默认宽度：260px 到 300px。
- 最小宽度：240px。
- 背景：浅灰或半透明灰，和主内容白底区分。
- 不使用厚重边框，用轻微分隔线或背景差异分层。

内容顺序：

1. 窗口控制区和返回/前进按钮。
2. 全局导航：
   - 快速对话
   - 搜索
   - 技能
   - 插件
   - 自动化
3. 项目分组：
   - 项目名
   - 项目下最近会话
   - 无会话时显示 `暂无对话`
4. 对话分组：
   - 不绑定项目的最近对话
   - 无聊天时显示 `暂无聊天`
5. 设置入口固定在底部。

交互要求：

- 当前项目或当前会话要有浅色选中背景。
- 长标题单行截断，右侧保留时间信息。
- 项目可折叠，后续可扩展右键菜单。
- 不在侧边栏里放复杂操作表单。

### 2.2 中间对话工作区

用途：承载主要需求沟通和 Agent 执行过程。

空态布局：

- 中心偏上显示标题：`我们应该在 voicecoder 中构建什么？`
- 标题下方放大输入框。
- 输入框下方显示项目、运行模式、分支等上下文。
- 内容区域留白充足，不放营销文案或说明卡片。

会话态布局：

- 顶部显示当前会话标题、模型/上下文状态和更多操作。
- 中间是消息流。
- 底部固定输入框。
- Agent 输出中可以嵌入文件卡片、变更摘要卡片、确认卡片。

输入框结构：

- 文本区域：支持多行，默认高度约 96px 到 132px。
- 左侧工具：添加附件/上下文、自动审查开关。
- 右侧工具：Agent provider、模型、推理强度、语音、发送。
- 下方上下文条：项目选择、本地模式、Git 分支。

输入框状态：

- 空闲：可输入，可选择项目。
- 录音中：显示录音状态、实时转写、停止按钮。
- 生成中：发送按钮变为停止或禁用状态。
- 待确认：显示 Coding Prompt 预览和确认按钮。
- 执行中：显示 Agent 步骤和日志摘要。
- 失败：显示可重试操作和错误摘要。

### 2.3 右侧工作区

用途：根据当前上下文展示开发辅助能力。

空态布局参考 `demo3.png`：

- 右侧区域居中显示 2 x 2 工具入口。
- 四个入口为：
  - 文件：浏览项目文件
  - 浏览器：打开网站或本地预览
  - 审查：查看代码更改
  - 终端：启动交互式 shell
- 卡片为浅灰底、低圆角、图标加标题加短副标题。

文件态布局参考 `demo1.png`：

- 顶部是文件 tab。
- tab 下方是面包屑路径。
- 主体左侧为代码查看器。
- 主体右侧为文件树，可搜索。
- 文件树可折叠，选中文件有浅色背景。

审查态布局：

- 顶部显示本轮变更摘要。
- 左侧或顶部显示文件变更列表。
- 主区显示 diff。
- 支持按文件打开、继续要求修改、回滚本轮变更。

浏览器态布局：

- 顶部显示地址、刷新、打开外部浏览器、停止 dev server。
- 主区为内嵌预览。
- 错误时显示启动命令、端口、stderr 摘要。

终端态布局：

- 顶部显示进程选择、清空、复制、停止。
- 主区显示日志流。
- 终端和 Agent 命令日志要有来源标识。

## 3. 核心页面状态

### 3.1 首次打开

条件：没有项目，没有历史会话。

界面：

- 左侧项目和对话都显示空态。
- 中间显示空态标题和输入框。
- 项目选择默认为 `不使用项目` 或引导添加项目。
- 右侧显示四个工具入口，但未选择项目时文件、审查、终端进入空态提示。

### 3.2 已选择项目，无会话

条件：已有当前项目，但还没有发起需求。

界面：

- 左侧项目高亮。
- 中间标题包含项目名，例如 `我们应该在 voicecoder 中构建什么？`
- 输入框下方显示当前项目、模式、Git 分支。
- 右侧显示工具入口，文件入口可直接打开文件树。

### 3.3 需求澄清中

条件：用户已输入需求，但结构化需求仍有不明确项。

界面：

- 消息流展示用户原始需求。
- AI 回复包含总结和追问。
- 可展示“当前需求”折叠摘要，但不要打断对话主线。
- 输入框提示用户补充信息。

### 3.4 待确认执行

条件：需求足够明确，可以生成 Coding Prompt。

界面：

- 中间显示 Coding Prompt 预览卡片。
- 卡片包含目标、修改范围、验收标准、风险提示。
- 操作按钮：确认执行、编辑 Prompt、继续补充、取消。
- 右侧可切到文件视图，辅助用户确认上下文。

### 3.5 Agent 执行中

条件：Codex 或其他 Coding Agent 正在处理。

界面：

- 消息流显示阶段性事件。
- 命令执行、文件读取、文件修改要有简洁状态，不刷屏。
- 输入框可以允许“追加要求”，但明确表示会排队或作为下一轮。
- 右侧终端可显示详细日志。

### 3.6 执行完成

条件：Agent 成功结束。

界面：

- 消息流显示完成总结。
- 展示变更摘要卡片：
  - 修改文件数量
  - 新增/删除行数
  - 关键文件列表
  - 审查按钮
  - 回滚按钮
- 右侧默认切到审查或文件视图。
- 输入框提示 `要求后续变更`。

### 3.7 执行失败

条件：Agent、ASR、文件系统、dev server 任一关键流程失败。

界面：

- 消息流显示人能理解的错误摘要。
- 详细日志放到右侧终端或可展开区域。
- 提供重试、复制诊断、返回编辑 Prompt 等动作。

## 4. 信息架构与组件建议

建议组件层级：

```text
App
  ├─ AppShell
  │  ├─ Sidebar
  │  │  ├─ GlobalNav
  │  │  ├─ ProjectList
  │  │  ├─ ConversationList
  │  │  └─ SettingsEntry
  │  ├─ ConversationPane
  │  │  ├─ ConversationHeader
  │  │  ├─ EmptyPrompt
  │  │  ├─ MessageTimeline
  │  │  ├─ RequirementSummaryCard
  │  │  ├─ CodingPromptCard
  │  │  ├─ ChangeSummaryCard
  │  │  └─ Composer
  │  └─ WorkspacePane
  │     ├─ WorkspaceLauncher
  │     ├─ FileWorkspace
  │     ├─ ReviewWorkspace
  │     ├─ BrowserWorkspace
  │     └─ TerminalWorkspace
  └─ AppProviders
     ├─ ProjectStateProvider
     ├─ ConversationStateProvider
     ├─ RequirementStateProvider
     ├─ AgentEventProvider
     └─ SettingsProvider
```

核心状态模型：

```ts
type WorkspaceMode = "launcher" | "files" | "review" | "browser" | "terminal";

type ConversationPhase =
  | "empty"
  | "collecting"
  | "clarifying"
  | "ready_to_confirm"
  | "agent_running"
  | "completed"
  | "failed";

type RequirementState = {
  goal?: string;
  pages: string[];
  components: string[];
  interactions: string[];
  visualConstraints: string[];
  technicalConstraints: string[];
  openQuestions: string[];
  acceptanceCriteria: string[];
};
```

## 5. 视觉规范

整体气质：

- 干净、克制、工具化。
- 信息密度接近 Codex App，而不是营销首页。
- 避免大面积彩色渐变、装饰图形和复杂背景。

颜色：

- 主背景：白色。
- 侧边栏：浅灰。
- 卡片/入口：极浅灰。
- 文本：深灰到黑。
- 次要文本：中灰。
- 强调色：蓝色，用于链接、当前操作、自动审查状态。
- 成功/删除：绿色和红色仅用于 diff 数字。

形状：

- 输入框和卡片使用 8px 到 16px 圆角。
- 工具卡片使用低对比度背景，不做厚重阴影。
- 文件树选中态使用浅灰背景。

字体：

- 使用系统字体。
- 代码区使用等宽字体。
- 不使用随视口宽度缩放的字体。
- 控件内文本必须单行可读，长文本截断。

图标：

- 优先使用 lucide-react 或现有图标库。
- 导航、工具入口、文件类型、按钮都使用图标加文字或纯图标。
- 不手写复杂 SVG 图标。

## 6. 交互细节

项目选择：

- 输入框下方项目 chip 可打开项目菜单。
- 菜单包含搜索项目、已有项目、添加新项目、不使用项目。
- 添加新项目二级菜单包含新建空白项目和使用现有文件夹。

自动审查：

- 作为输入框工具条里的开关或下拉。
- 开启时，Agent 完成后默认进入审查视图。
- 关闭时，Agent 完成后只展示摘要，用户可手动打开审查。

模型和推理强度：

- 模型显示为短标签，例如 `sub2api`。
- 推理强度显示为数值和文字，例如 `5.5 超高`。
- 具体模型设置放到设置页，不在主界面展开复杂表单。

语音：

- 麦克风按钮在发送按钮附近。
- 录音时按钮状态明显变化。
- 实时转写可以先进入输入框草稿，final 结果再提交到消息流。
- 多人转写在消息流中按 speaker 分组显示。

文件树：

- 文件夹可展开/收起。
- 当前文件高亮。
- 支持搜索过滤。
- 常见文件类型显示不同图标。

右侧工作区切换：

- 空态用四个入口。
- 进入某个工作区后，顶部保留切换入口或 tab。
- 中间对话不因右侧工作区切换而丢失滚动状态。

## 7. 前端与后端边界

前端负责：

- 布局、组件、交互状态。
- 消息流和事件流展示。
- 输入框、菜单、工作区切换。
- 文件内容、diff、日志的渲染。

Tauri/Rust 后端负责：

- 本地项目选择和权限。
- 文件系统读取、写入、监听。
- 路径标准化。
- 子进程管理：dev server、Codex、终端。
- ASR 鉴权、WebSocket 代理和音频处理。
- 敏感凭证读取和安全存储。

禁止：

- 前端直接持有腾讯云 SecretKey。
- 前端手写系统路径拼接。
- UI 默认自动修改用户真实项目。
- 把某个操作系统专用命令写进通用前端逻辑。

## 8. 开发优先级

第一轮页面开发顺序：

1. AppShell：左侧导航、中间空态、右侧工具入口。
2. Project Picker：添加项目、切换项目、侧边栏项目状态。
3. Composer：文本输入、工具条、发送状态。
4. Message Timeline：用户消息、AI 消息、系统状态。
5. File Workspace：文件树、文件打开、代码查看。
6. Requirement Cards：需求摘要、追问、Coding Prompt 确认。
7. Change Summary：执行完成后的文件变更摘要。
8. Review Workspace：文件 diff 和回滚入口。
9. Browser Workspace：本地预览。
10. Terminal Workspace：日志和进程控制。

## 9. 验收清单

布局验收：

- 侧边栏、中间对话、右侧工作区在 1440px 以上宽度下完整展示。
- 在较窄窗口下右侧工作区可以折叠。
- 输入框、菜单、卡片文本不溢出。
- 消息流和右侧工作区滚动互不影响。

功能验收：

- 可以添加并切换本地项目。
- 可以输入需求并生成消息。
- 可以打开文件树并查看文件内容。
- 可以展示需求摘要和待澄清问题。
- 可以展示 Coding Prompt 确认卡片。
- 可以展示 Agent 变更摘要。

体验验收：

- 首屏不出现开发说明或营销文案。
- 未实现能力有明确空态，不是无反应按钮。
- 失败状态提供下一步动作。
- 用户始终知道当前项目、当前会话、当前执行阶段。
